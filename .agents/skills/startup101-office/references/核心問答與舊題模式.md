# 核心問答與舊題模式

先以 inspect（專案檢查）的 core_mode 與正式 YAML 判斷目前內容。題數、問題識別與可用命令不能靠記憶、畫面標題或複製文字猜測。

| 項目 | 核心問答模式 | 舊題模式 |
|---|---|---|
| 目前內容 | core_canvas.questions | questions |
| 問答單位 | 十主題下的20個核心問題，共用完整答案 | 原351題及各自requirements |
| 相近問法／追問 | 同核心答案的補充，不各要一份回答 | 保留原題引用，按既有評估流程處理 |
| 保存 | 明確編輯Markdown，再由sync_core.py回填同一YAML | note／draft／evaluate-input／accept等原生命令 |
| Headlines | core_canvas內中英配對headlines | 原key_points.items單語陣列，依該正文語言；不塞兩組翻譯 |
| 進度 | 已填，不代表已通過 | 有效接受的原題 |
| 正式評估 | 此版未提供核心原生評估packet與accept | 既有四維rubric、逐題requirements與複核gate |

## 核心問答的工作方式

每輪先讀全部核心題目與已存完整答案，分析使用者整份回答的分布，再進行霰彈式的拆解。一次只問一個待答部分，但一次回答可以補充多個核心問題。相近問法仍共用所屬核心答案，不把來源原題重新問一輪。

### 霰彈式拆解與同步前核對

- 以每段實際回答的問題決定歸屬。前段講痛點、後段講產品功能及目標時，分別補入對應問題；不因當下問的是公司業務與目標，就把全文只塞進該題。
- 寫入前先在對話列出「片段內容 → 題目名稱」，說清楚本輪涉及哪些部分。用目前題庫的真實題目，不自創題目或只列代號。這是說明既有回答的歸屬，通常可直接繼續保存；只有意思、撤回或歸屬真的有歧義時，才釐清受影響的部分。
- 按題意整理完整答案，保留角色、數字、因果、時序、條件、假設、目標與已發生事實的差別。每題離開原對話仍要讀得懂。同一段可以支持多題，但每題只寫與題意相關的主張及必要上下文，不把全文重複貼到各題。沒有合適歸屬的實質片段先保留在整理稿，釐清歸屬後再同步，不能默默丟掉或硬塞。
- 舊答案已有的內容直接沿用；本輪補充要合併，明確撤回的內容要更新所有受影響題目。出現互相衝突的說法時先指出前後文，未釐清的部分不覆蓋正式資料，其他明確內容可先保存。
- 同步前逐段確認都有合適落點或明確待釐清原因，再逐題確認正文直接回答該題。特別核對 pricing 與 GTM、Adopter 與 traction、市場規模與導入策略的邊界；不同題可以引用必要上下文，但不能用另一題的內容取代本題答案。不得用「未確認」旁白取代使用者已提供的實際工作。
- 核對中英正文與headlines的主張及限定一致，再對整份編輯稿預覽並以同一次來源hash套用。重讀全部本輪修改的題目，確認內容及已填進度。已填只代表存有內容，不代表完整或已正式通過。

### 從更新後的分布找下一個 bottleneck

先沿用使用者明確選題或範圍；其餘從全部已存答案判斷哪個尚未回答、矛盾或缺少必要依據的部分，最影響目前決策或其他題的理解。下一問用一句話交代選它的原因，再只問那一個部分。不要機械跳到下一個空白題，也不要因為上一題仍有追問就一直停在同一題。使用者在別題已經講過的內容，先拆解補入，不能要求再答一次。只有外部驗證才能補足時，保存待驗證狀態並說明所需行動，不靠持續追問製造答案。

修改正文後再按headlines規則核對中英便條紙，保留使用者已確認的表達；只改headline時不重寫正文。不直接手改core的來源hash，不拿舊題的分數裝成核心通過。使用者要求正式核心scoring時，明確說明此版沒有受支援的packet與接受寫入，不能手填分數或偽造舊題packet；可繼續討論論點與證據，不能宣稱正式通過。

同步細節依使用方式的核心回填章節。Markdown是使用者要求的編輯稿；執行明確回填後，Canvas只讀YAML。檔案衝突先整合，不能用舊副本強蓋。來源對應檔只存身份與引用，不是另一份答案。

舊題模式的正文與headlines保留原語言，畫面切換只翻譯介面／題目，不自動翻譯這些內容；核心模式才保存成對中英文答案與headlines。

## 從零與續跑的邊界

init 建立基礎 YAML。若要從指定的 20 題核心 Canvas 起步，使用該題庫的中英文題目、分類、追問與來源對應檔，建立空白編輯稿並執行 sync_core.py，再以 inspect 確認 20 題、0 已填。每題的雙語答案可同時留空，空題的 headlines 也留空。錄影或訪談時按每輪回答的拆解更新同一份編輯稿中的相關題目，每次同步後依全題分布找下一個bottleneck。核心進度使用已填，原生評分與 accept 只支援舊題模式。

已有core_canvas時，skills不再將封存來源題當作目前必答題。未啟用時保留原流程，不自動改題庫或升級專案固定rules。

## 三支技能的分工

Office定位版本、拆解本輪回答到適合題目、整理與保存正文／headlines、同步及驗收。Facilitation依office交付的全題分布選下一個bottleneck，釐清當前核心或原題，不另外產生第二份便條紙或自行宣告通過。Evaluate只評受支援packet的完整候選；headline長度與外觀不計入原分數，不能用摘要代替正文。

## 舊題模式的跨題內容

舊題模式同樣分析整份回答、先說明片段與原題的對應。一份整理筆記可以關聯多個原題，沿用同一筆記識別與對應段落，避免重複保存。各題的draft與候選只使用相關內容，依原生命令各自建立packet、評估及接受；某題通過不會讓其他題一起通過。選下一個bottleneck時先讀已有筆記，不能因尚未建立另一題的draft就重問已提供的內容。

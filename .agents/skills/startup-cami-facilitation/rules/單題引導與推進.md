# Rule 1 - 一次一個待答部分
- Level: `MUST`
- 目前問題的英文與id不改；核心模式依全題分布一次釐清一件事，收到回答後交office按共用模式reference拆解至適合題目。舊題模式才依required part逐項推進。原題可完整顯示，但不要把五個追問塞在同一回合。
- 優先使用者選題；其餘依office交付的全題分布找下一個bottleneck，核對其他題與筆記是否已有答案，再選最影響目前決策的一個待答部分。
- 依office共用模式reference辨識來源。核心模式一個核心問題共用一份答案，相近問法／追問不新增必答題；舊題模式才保留獨立原題與id。11個caution只屬舊題提醒，不推薦作填答。
## Good Example
```text
原題問誰使用、誰付款、誰控制採購。
本回合只問：Who uses the product?
待此部分清楚後再問付款者；核心模式補入同一答案；舊題模式全部必要部分完整才送原題評估。
```
## Bad Example
```text
一次追問使用者、付款者、決策者、預算、採購時程，另外創五個題號。
```
# Rule 2 - 解釋不能變成代答
- Level: `MUST`
- 舊題模式的逐題why/example/avoid從pinned catalog.help讀取；核心模式依目前完整答案及已存追問解釋，不要求不存在的catalog.help或編造教材範例。範例永遠明示 synthetic，不把它混進訪談筆記、claims 或答案。
- 受訪者題需要使用者提供實際受訪內容，不能讓創辦人扮演不存在的顧客。沒有資料可延後，不生成客戶姓名、付款或觀察。
- 使用者答不知道時，協助指出需要什麼資訊；有足夠內容時核心交office保存，舊題才立即送評，不為嚴格再問兩輪。
## Good Example
```text
這是示例，不是你的資料。請提供你最近一次訪談中顧客描述的事件；尚未訪談可先跳過。
```
## Bad Example
```text
為了讓你過關，我先替客戶假設每週浪費十小時，寫進正式答案。
```
# Rule 3 - 追問只針對改判資訊
- Level: `MUST`
- 舊題模式依evaluator候選、筆記引用、理由與next_question追問；核心模式沒有受支援packet時，依當前正文與明確追問釐清，不自行造評分結果。不自行調分或加入新的硬門檻。每次只追最關鍵的一件事。
- 同一阻擋點兩輪仍無新資訊，建議先做研究、延後或換題；使用者想繼續可繼續，但不能用順從或疲憊交換pass；核心模式不宣稱正式pass。
- 不把使用者明示撤回的舊句當目前立場。AI 必須推論如何合併時，提出一個候選請確認，不能悄悄重寫。
## Good Example
```text
你說「有興趣，所以會付費」。目前只能支持有興趣；他實際承諾了什麼？
```
## Bad Example
```text
你沒有接受我的建議，所以我把自洽再扣一分。
```

# Rule 4 - 先辨識模式，再沿用同一份 context

- Level: `MUST`
- 核心模式依共用模式reference讀全題分布，再讀本輪涉及的核心答案。相近問法、追問與評估條件只釐清同一答案，不因來源有多個id而重複問；不得替核心來源題複製分數。
- 舊題模式才逐原題讀來源、audience與requirements，引用同卡已知背景，只追當前原題真正缺的部分。另一面的反證或不同條件仍需保留，不能以背景重用省略。
- 11道caution只解釋錯誤問法，不選成待回答題。兩種模式都不以讀過卡片代替提供證據。

## Good Example

```text
核心問題問誰使用、誰付費與採購決定。已有使用者背景，只釐清付款者，補入同一核心答案，不另開三份回答。舊題模式仍依原題引用與評估，不把使用者自動視為付費者。
```

## Bad Example

```text
核心答案已有全部資訊，仍把來源題逐一重問；或將舊題主問題通過複製給同卡其他原題。
```

# Rule 5 - 追問必須影響決策並保留誠實狀態

- Level: `MUST`
- 依共用 `../startup-cami-office/references/決策判斷與誠實回答.md`（決策判斷與獨立複核）區分有、沒有、不知道與尚未驗證；不知道不作道德扣分，也不自動滿足事實題要求。
- 使用者選題優先，其餘依會改變當前決策的資訊選題。只能外部驗證時交回一個實驗與觀察，不拿聊天上的漂亮句子替代證據。
- 新舊回答可能矛盾時引用兩方與版本，先釐清時間／對象／撤回含義，舊題模式再交office重評；核心模式釐清後更新同一正文，不宣稱有正式重評；不直接改舊答案。強烈提醒只依共用 reference 的反覆迴避條件，不能因初問含糊、未知、不同意或隱私拒絕觸發。

## Good Example

使用者說還沒向人收費：明記尚未驗證付款意願，下一步做有價格的試行邀請，不繼續要求把「可能付費」說得更肯定。

## Bad Example

使用者說不知道，就責備不夠誠實；或接受「應該很多人會買」作為已驗證答案。

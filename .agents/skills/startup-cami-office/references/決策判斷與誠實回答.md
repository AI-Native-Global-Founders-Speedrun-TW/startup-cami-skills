# 決策判斷、誠實回答與獨立複核

這份 reference 由 office、facilitation 與 evaluate 共同讀取。原題、逐題 requirements、四維 scoring 與正式接受仍依 pinned 契約。決策判斷另存，不能把回答 pass 說成創業會成功，也不能因決策尚缺外部證據而竄改原本的回答分數。

## 回答通過與決策依據分開

每輪先標示現在要做的具體決策；尚無決策時如實記為未指定，不虛構。交代這份回答能支持什麼、有哪些已知證據、哪些沒有或還沒驗證，以及什麼新資訊會改變判斷。可清楚記錄的假設仍是假設，不會因四維滿分變成已驗證市場需求。這份判斷不產生成功率或另一個創業總分。

下一題優先選最可能改變當前決策的缺少資訊，說明它為何會影響選擇；不要只為完成卡片順序而問。使用者明確選題優先。資訊只能在外部取得時，提出一個能取得資訊的實驗或研究行動，列出觀察什麼、什麼結果會改變判斷；使用者尚未做就不能寫成已做。可保存待查與理由，停止無效的聊天追問。

選題交接用一段話保留「當前決策／目前缺的資訊／知道後哪個選擇可能改變／這次問句能取得什麼」。這是引導理由，不是新增必填評分欄位。沒有當前決策時沿用使用者選題或既有未完成題，明說決策未指定；不為填模板創造決策，也不強制使用者先接受 AI 選定的決策。

若對方已清楚說「沒有做過」，下一輪不能再換句話要求他給那個不存在的結果。外部實驗交接要說明要接觸的對象或可用來源、實際要做的動作、要記錄的觀察，以及不同觀察如何影響選擇；尚無足夠背景就指出缺哪一項，不自訂人數、預算、期限或成功門檻。可先保存待查理由，回來後依實際觀察續跑。

## 誠實狀態必須說清楚

把「有」「沒有」「不知道」「尚未驗證」分開。有就指出具體已發生內容與來源；沒有就承認沒有；不知道不等於沒有；尚未驗證不等於已被推翻。使用者不願揭露私人資訊時可明示不提供，不能假裝來源已查核，也不能把拒絕提供視為逃避。狀態明確但題目必要部分尚缺時，記錄缺少資訊與下一個行動，不把誠實未知自動改成已通過，也不羞辱未知。

只質疑會改變決策、風險高或缺少支持的主張。引用已保存筆記或正式答案的相關句子，附來源識別，再指出隱含前提、可替代解釋與可能推翻它的觀察。不要為了看起來嚴厲，對每句話都反駁；有理由反對 AI 時重看理由。

使用者要求的強句是：「你這樣逃避根本不可能創業」。只有在同一個清楚問題已解釋、使用者有機會澄清，仍有多輪有筆記可追溯的迴避時，才可引用這句作為對當前行為的嚴厲提醒；必須同時指出是哪個問題、哪兩次回答避開了它，並只問一個可直接回答的問題。不能把這句當成對成功機率的事實判斷、人格定論或習慣性開場。不知道、尚未驗證、有理由不同意、需要時間或隱私拒絕，都不滿足觸發條件；拿不出具體紀錄就不使用。

## 主動找前後矛盾，但不代替使用者改答案

讀取與當前決策相關的既有正式回答。發現衝突時提出「舊候選／新筆記／為何不能同時成立」，來源帶原題與版本；先區分時間變化、適用對象不同、撤回與真矛盾。請使用者確認更新含義，再對確認後的候選重新評估。保留舊版與本次整理後的筆記，不能靜默覆寫、重用舊分數或自動宣告舊回答錯誤。純粹發現潛在矛盾不是使用者已同意撤回。

確認時列出舊題與舊版候選、新筆記及來源識別，明示後者是整理稿，問這是時間或對象不同、修正舊主張，還是尚未確定。確認新事實不等於同意 AI 改寫整段答案；只有確認影響哪一道舊回答及新的候選內容後，office 才依既有流程重評該題。一次只處理會影響當前判斷的衝突，不默默將整張卡或其他依賴答案全部重寫。尚未確認時，回饋明示「矛盾待確認，舊正式回答保留」。

## 關鍵或邊界判斷由第二位 evaluator 盲審

涉及當前重大投入、難以撤回的決策、重要且未支持的前提，或 verdict／要求適用範圍處於邊界時，office 記錄具體理由並啟用獨立複核。一般充分且低風險回答不強制雙重追問。

第二位只收到相同原題、候選版本、來源、依賴與 pinned 規則，以及中性的當前決策描述；不收到第一位 verdict、分數、feedback、期望結果或帶結論的摘要。獨立不是同一個 evaluator 看完答案後假裝換角色；host 無法派出獨立 evaluator 時如實標示不可用，不能編造第二份審查或宣稱已有共識。

兩份結果到齊後 office 比較引用、要求適用與推論理由，不平均分數、不投票，也不透過提示第二位「第一位已經通過」促成一致。若歧見只是查到來源或規則誤讀，保留原審查並另記更正理由；若仍無法解決，清楚列出爭點、缺少資訊與下一步，不能宣稱共識或逼使用者接受 AI 指定措辭。需要重新候選時仍由使用者確認，舊版審查不能代替新版本。

正式寫入是否可進行，依 runtime contract 的複核 gate 執行；不得因使用者已等很久、某位分數較高或第二位不可用而繞過。decision review 與原有 evaluation 分開保存，不能以事後補寫的共識紀錄取代實際獨立判斷。

## 執行契約

關鍵判斷先在 `evaluate-input --review-policy independent` 選定政策，再派第一位 evaluator。預設 single 不代表任何回答都適合單人評估；office 必須先依上述條件判斷。若首次評估後才發現 borderline，重新建立 independent packet，針對新 packet 取得兩份全新盲審；不得把舊 single pass 搬過來。既有 accepted 歷史不因新增政策回溯改寫。

派第二位必須使用 host 真正隔離的 subagent；例如支援時使用 `fork_turns: none`，只交必要 packet 與規則，不帶已含第一份結果的聊天上下文。不同 evaluator 名字只是 runtime 可檢查的識別條件，不證明 host 真的隔離；office 必須如實執行。

兩份 EvaluationResult 先各自 `record-evaluation`，再用 `record-review --review <JSON檔>` 保存：

- review_id、question_id、input_sha256：當前 review 與 packet 識別。
- evaluation_ids：只引用實際已記錄且同 packet 的結果；agreed 必須兩份 pass、不同 evaluator。unresolved／unavailable 可有零到兩份實際結果，缺少第二位時不可編造識別或結果。
- resolution：agreed、unresolved 或 unavailable。
- resolution_reasons：比較要求與引用後的非空理由，不只寫「兩人都通過」。
- reviewed_at：實際審查時間。

independent 接受須有最新相符 agreed review 且包含即將接受的結果。unresolved／unavailable 不得接受。兩份同為 revise 時不宣稱可接受，仍依阻擋點處理；不得把其中一份改名冒充第二人。

`record-decision --assessment <JSON檔>` 另存：assessment_id、question_id、input_sha256、evaluation_id、decision、status（ready／not_ready／unknown）、evidence_refs（packet 中來源或筆記識別）、missing_information、what_changes_verdict、assessor、assessed_at。這份判斷保存於共用 YAML 的 records，不是第二套正式答案，也不新增 scoring。ready 只指所述範圍的決策依據，不是預測成功。檢視時核對來源版本／hash；來源變動後舊判斷不得當成現況。實際欄位與驗證以 runtime contract 為準，不能手填假的證據或評估識別。

公司目的或反思可以按本題要求通過，而投資決策仍 not_ready；後者本身不阻擋前者接受。複核 gate 檢查的是該候選的獨立評估要求，不把商業就緒性塞進無關原題的門檻。

尚未接受可先記 assessment 供追查；accept 會改來源版本，接受前的 assessment 可能因此 stale。成功接受後要呈現 current decision assessment，須核對已提交 receipt，使用新的 assessment_id 另記；不覆寫舊判斷紀錄，不把舊來源判斷冒充最新。single 升級 independent 不需要偽造新 user turn；runtime 允許單向升級並重建 packet，仍須兩份全新盲評，禁止同一批筆記降級為 single。

## 回饋狀態不能含糊

模板各欄使用當前實際狀態。needs_context 的分數為 null，呈現「尚不能評分」，不顯示0分或沿用舊分數。單題 pass、複核未完成、決策 not_ready 與正式尚未接受可以同時成立，分別說明，不用一個「通過」包住全部。

未需要複核寫「本輪採單一評估」；需要但找不到獨立 evaluator 寫「複核不可用，正式接受暫停」；兩人不同意寫具體分歧；兩份符合要求的結果完成才寫已完成複核。不要將「如果需要複核」這類未決條件留給使用者猜。沒有實際執行保存命令，就不能說已保存；尚無 evaluation 可關聯時，決策先作對話建議，不能捏造 evaluation_id 呼叫 record-decision。

決策標 ready 前，先指出具體適用範圍、實際支持它的來源或訪談筆記，以及已知限制。沒有當前決策時用未指定／unknown，不為填欄位說 ready。沒有可引用支持時不能憑空宣稱 ready；個人價值或反思的選擇可以引用使用者已確認的候選或筆記，標自述，不假稱外部查核。not_ready 或缺少資訊描述的是該決策目前的依據，不是對誠實程度扣分，也不是額外的單題 pass 門檻。

每次回饋不必重複整張模板。保留當前 verdict、與本題相關的誠實狀態、單一下一步與實際保存結果；決策、證據、限制或複核狀態有變化時才展開對應欄位。沒有變化可簡短指向前次，不把真正的新分歧、未知或 stale 隱去。模板是完整檢查骨架，不是要求每答一句就輸出十欄。
